## Adversarial review round 2

Four reviews (SQL, phases 1–3, phases 4/5/8, phases 6/7/9/10). Confirmed and fixed:

**Database**

- `sms_delivery_kind` gained an unused `deferral` label. A label cannot be dropped from a
  Postgres enum, so it would have been permanent. Removed from the unshipped migration.
- The readiness probe hardcoded `confirm_manual_exception_aadhaar_authenticated_execute` and
  `_anon_execute` to `false` instead of calling `has_function_privilege`. Two grant assertions
  that could never fail. Now measured.
- `confirm_manual_exception_aadhaar` commit-mode, key-free path took no row lock (there is no
  row to lock), so two desks confirming the same card both saw `free` and the loser hit a raw
  `23505`. Now caught and re-raised as `AADHAAR_KEY_TAKEN`, mapped to a Hinglish re-scan
  instruction.
- Dead `CASE WHEN p_keep_display_name THEN pe.display_name ELSE pe.display_name END` removed.

**SMS**

- `assertSmsSegments` ran on no send path — `fill*Sms` were called only by tests while the
  senders used `*SmsVariables` directly. The segment cap now applies before dispatch, with a
  regression test that asserts nothing is sent.
- `MSG91_TEMPLATE_DEFERRAL` was absent from the readiness/env check, so readiness reported SMS
  green while every deferral message returned `unconfigured` forever.
- `sendDeferralSms` skipped the configured-check whenever a send function was injected and fell
  back to `"test"` / `"TESTID"` / `"test-template"` credentials. Now refuses unconditionally.
- The T-1 job sent unledgered when the slip → item → transcription → patient join missed,
  so the next cron run re-sent. A deferral without a ledger claim is now skipped.
- Venue truncation cut on code points, splitting Devanagari grapheme clusters. Now uses
  `Intl.Segmenter`. The reminder max-length fixture was Latin `"A"`; it is Devanagari now.
- Dead `GSM7_RE` / `isGsm7` / `assertGsm7` deleted — Phase 5 replaced GSM-7 with segment counting.

**Desk and clinical surfaces**

- `/api/desk/aadhaar-confirm` and `/api/desk/register-manual` collapsed every RPC refusal into one
  generic 409 that named no next action, discarding the Hinglish text `public-error.ts` already
  held. Both now map through `mapDbError`.
- The confirmation diff rendered only name, date of birth and address. `gender` and
  `aadhaarLast4` are in the changed set and overwrite the Person, so a wrong card could be
  accepted unseen. All five locked fields are shown.
- The three confirmation fetches had `try/finally` with no `catch`; a network drop left the card
  silent and produced an unhandled rejection.
- `ClinicalDesk` read `localStorage` inside a `useState` initializer — a hydration mismatch on
  every reload with a non-default line. Replaced with `useSyncExternalStore`, which also removed
  the separate persistence effect.
- A failed `list_ot_schedule_days` cleared the day list and produced "Saari OT dates bhar gayi",
  pointing the operator at the admin for a problem the admin cannot fix.
- `otherSpecsLine` was exported and tested but never used; the outcome-conflict refusal did not
  name the other line as Phase 6 requires. Now wired in.
- The clinical desk rendered English line labels on an otherwise Hinglish surface. Labels are
  Hinglish; `e2e/clinical-lines.spec.ts` follows.

**Slip**

- `font-display:swap` plus an immediate `window.print()` could rasterise the slip before the
  bundled Devanagari font loaded — the blank-slip failure ADR 0008 exists to prevent. Now
  `font-display:block` and `AutoPrint` waits on `document.fonts.ready`.
- The issue timestamp used `toLocaleString("en-IN")` with no `timeZone`, so a slip issued after
  midnight IST printed the previous calendar day when rendered on a UTC server.
- Raw DB gender (`M`/`F`) printed Latin on a Devanagari slip.

**Tests**

- `tests/ot-schedule.db.test.mjs` asserted on `pg_get_functiondef` source text — the brittle
  pattern the testing rules discourage, and one that passes on rot. Rewritten to exercise
  `upsert_ot_schedule_day` behaviourally, including the no-day-id path that round 1 had left
  without the `SEAT_LIMIT_BELOW_ASSIGNED` guard.

### Declined

- `clinical_resolve_item` raises `OT_SCHEDULE_FULL` when an explicitly supplied schedule-day id
  does not resolve. The id can only come from the server-rendered list and schedule days have no
  delete path, so the branch is unreachable in practice. Left as is rather than adding a second
  refusal identifier.
- `/volunteer`'s header subtitle is computed from the server seed rather than the poll. The
  actions themselves ride the poll, which is what user story 3 requires; the subtitle is
  cosmetic.

### Not a defect

- A review claimed `check:js-budget` would fail because `/lookup` and `/s/[token]` still exist.
  Only empty directories remained, Next emits no route for them, and the check passes. The empty
  directories were removed anyway.

enum label and the false grant assertions were fixed in place rather than appended, because a

migration at or before `20260814100000`.
