## Adversarial review round 2

Four reviews (SQL, phases 1–3, phases 4/5/8, phases 6/7/9/10). Confirmed and fixed:

**Database**

- `sms_delivery_kind` gained an unused `deferral` label. A label cannot be dropped from a
  Postgres enum, so it would have been permanent. Removed from the unshipped migration.
- The readiness probe hardcoded `confirm_manual_exception_aadhaar_authenticated_execute` and
  `_anon_execute` to `false` instead of calling `has_function_privilege`. Two grant assertions
  that could never fail. Now measured.
- `confirm_manual_exception_aadhaar` commit-mode, key-free path took no row lock (there is no
  row to lock), so two desks confirming the same card both saw `free` and the loser hit a raw
  `23505`. Now caught and re-raised as `AADHAAR_KEY_TAKEN`, mapped to a Hinglish re-scan
  instruction.
- Dead `CASE WHEN p_keep_display_name THEN pe.display_name ELSE pe.display_name END` removed.

**SMS**

- `assertSmsSegments` ran on no send path — `fill*Sms` were called only by tests while the
  senders used `*SmsVariables` directly. The segment cap now applies before dispatch, with a
  regression test that asserts nothing is sent.
- `MSG91_TEMPLATE_DEFERRAL` was absent from the readiness/env check, so readiness reported SMS
  green while every deferral message returned `unconfigured` forever.
- `sendDeferralSms` skipped the configured-check whenever a send function was injected and fell
  back to `"test"` / `"TESTID"` / `"test-template"` credentials. Now refuses unconditionally.
- The T-1 job sent unledgered when the slip → item → transcription → patient join missed,
  so the next cron run re-sent. A deferral without a ledger claim is now skipped.
- Venue truncation cut on code points, splitting Devanagari grapheme clusters. Now uses
  `Intl.Segmenter`. The reminder max-length fixture was Latin `"A"`; it is Devanagari now.
- Dead `GSM7_RE` / `isGsm7` / `assertGsm7` deleted — Phase 5 replaced GSM-7 with segment counting.

**Desk and clinical surfaces**

- `/api/desk/aadhaar-confirm` and `/api/desk/register-manual` collapsed every RPC refusal into one
  generic 409 that named no next action, discarding the Hinglish text `public-error.ts` already
  held. Both now map through `mapDbError`.
- The confirmation diff rendered only name, date of birth and address. `gender` and
  `aadhaarLast4` are in the changed set and overwrite the Person, so a wrong card could be
  accepted unseen. All five locked fields are shown.
- The three confirmation fetches had `try/finally` with no `catch`; a network drop left the card
  silent and produced an unhandled rejection.
- `ClinicalDesk` read `localStorage` inside a `useState` initializer — a hydration mismatch on
  every reload with a non-default line. Replaced with `useSyncExternalStore`, which also removed
  the separate persistence effect.
- A failed `list_ot_schedule_days` cleared the day list and produced "Saari OT dates bhar gayi",
  pointing the operator at the admin for a problem the admin cannot fix.
- `otherSpecsLine` was exported and tested but never used; the outcome-conflict refusal did not
  name the other line as Phase 6 requires. Now wired in.
- The clinical desk rendered English line labels on an otherwise Hinglish surface. Labels are
  Hinglish; `e2e/clinical-lines.spec.ts` follows.

**Slip**

- `font-display:swap` plus an immediate `window.print()` could rasterise the slip before the
  bundled Devanagari font loaded — the blank-slip failure ADR 0008 exists to prevent. Now
  `font-display:block` and `AutoPrint` waits on `document.fonts.ready`.
- The issue timestamp used `toLocaleString("en-IN")` with no `timeZone`, so a slip issued after

- Raw DB gender (`M`/`F`) printed Latin on a Devanagari slip.

## Review round 3 — what CI's database legs caught

The first push turned `verify` red: 32 of 179 database tests failed. Those legs cannot run
locally (no Docker), so CI was the first place this work met a real Postgres. Three of the
failures were product defects, not test drift.

**Product defects**

- **The two-attempt manual exception was refused by the database.** Phase 1 lowered the
  threshold from three to two in the client, the API route and the RPC, but not in
  `patients_manual_exception_check`, which still demanded `failed_scan_attempts >= 3`. A
  volunteer registering at exactly two failed scans hit a check-constraint violation — the
  whole point of Phase 1 failed at the last step. The constraint is now part of the Phase 1
  migration.
- **`readiness_catalog_probe()` threw at migration head.** The frozen probe still called
  `has_column_privilege(..., 'status_token', 'SELECT')`, and that raises `42703` on a dropped
  column rather than returning false. Every readiness check that reads the catalogue —
  `schema_contract` and `rpc_grants` — was broken in production by Phase 4.
- **`patient_registration_notify_fields` still selected and returned `status_token`.** Phase 4
  removed the link from the SMS but never updated the RPC that supplies the variables, so the
  registration-SMS path raised `column p.status_token does not exist` at head. Dropped and
  recreated without the column, with grants re-applied.

**Test drift from Phase 4 and Phase 2**

- `tests/status-token.db.test.mjs` exercised the retired RPC end to end; deleted, with the
  `.db.test.mjs` count guard moved from 34 to 33. `tests/status-retired.db.test.mjs` already
  covers the retirement.
- `status_token` removed from the seed inserts and grant assertions in
  `patient-read-boundary`, `patient-auth-retirement`, `adversarial-remediation` and
  `print-presence`.
- Fixtures that print now open the print window, or assert the refusal where the day is in the
  future — `print-presence` and `person-migrate`. Printing a future camp day being refused is
  Phase 2 working, so that case became its own test.
- `tests/aadhaar-confirmation.db.test.mjs` seeded a profile with no `auth.users` row and
  accepted "Patient not found" as a pass, so it asserted nothing about the RPC. Rewritten to
  register a real manual exception and check the null key, inspect-mutates-nothing, the commit
  overwrite and locks, the retained pre-overwrite values, the Latin display name, the collision
  outcome, and the volunteer override refusal.
- `tests/ot-schedule.db.test.mjs` compared `pg_get_function_identity_arguments` against a
  types-only string; that view includes parameter names.
- `undo and first transcription cannot both commit` was an unhandled rejection when the racing
  save lost before a handler was attached. It already failed on `main` at the commit this
  branch forked from, so it is pre-existing, but it was fixed here to get the check green.

## Review round 4 — the rewritten test earned its keep immediately

The second CI run cut the database failures from 32 to 4, all four in the rewritten
`aadhaar-confirmation.db` suite, all raising `structure of query does not match function
result type`.

**`confirm_manual_exception_aadhaar` never returned successfully on any path.**
`persons.aadhaar_last4` is `character(4)`; the function declares `typed_aadhaar_last4 text`.
PL/pgSQL rejects that in `RETURN QUERY`, so every mode — `not_required`, `needs_scan`,
`overridden`, `free`, `collision`, `committed`, `merged` — raised. Phase 3's whole flow was
dead on arrival. The old test accepted an `Error` as a passing outcome, which is precisely how
this survived review, the offline gate, and the first CI round. All seven `RETURN QUERY`
statements now cast to `text`.

## Review round 6 — the last Playwright failure

37 of 38 specs passed. The one that failed —
`print-window.spec.ts › the print URL renders a refusal card while the window is closed` —
mocked the client-side `/api/desk/live` response to report the window closed, but `/print/[id]`
is a server component that reads `camp_days.printing_open` from the database, where global
setup opens it. The route's refusal is correct; the test could never reach it. It now closes
the window through the service role, asserts the server-rendered refusal, and reopens it in a
`finally` — safe because the Playwright config runs one worker with `fullyParallel: false`.
